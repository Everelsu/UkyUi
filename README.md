# UltraKill Yourself UI — мод интерфейса для 1.12.2

Заменяет ванильные экраны Minecraft на собственные: загрузочный экран, главное
меню, настройки, меню паузы. Всё рисуется кодом (без текстур виджетов), палитра
и поведение задаются конфигом — под техсборку.

Тулчейн: **RetroFuturaGradle** (умеет 1.12.2 наравне с 1.7.10, в отличие от
устаревшего ForgeGradle 2.3).

Все настройки — в [CONFIG.md](CONFIG.md): ссылки с иконками, подсказки на
загрузке, сцена смерти, палитра.

## Требования
- JDK 8 для самого мода (RFG подтянет тулчейн сам)
- **JDK 25 для демона Gradle** — плагин RFG собран под него.
  В `gradle.properties` проекта это прописано, но глобальный
  `~/.gradle/gradle.properties` имеет приоритет и может перебивать значение.
  Если сборка падает с `UnsupportedClassVersionError`, запускай так:
  ```
  ./gradlew build -Dorg.gradle.java.home="C:\Program Files\Eclipse Adoptium\jdk-25.0.3.9-hotspot"
  ```
- Интернет-доступ к `nexus.gtnewhorizons.com`, `maven.cleanroommc.com` и
  стандартным Maven/Mojang/Forge репозиториям
- **MixinBooter** в сборке (в 1.12.2 он заменяет UniMixins): мод — coremod и без
  него mixin-конфиг не применится

## Сборка и запуск
```
./gradlew build
```
```
./gradlew runClient
```

## Чёрная дыра

Рисуется кодом (`BlackHole.java`).

Линзирование считается аналитически. Полное интегрирование геодезических (как в
CUDA-рейтрейсерах) на кадр не потянуть, но для точечного источника у
шварцшильдовской линзы есть замкнутое решение, а звёздное небо — это и есть
точки. Для звезды на угловом расстоянии `b` от сингулярности при радиусе
Эйнштейна `Te`:

```
T+ = (b + sqrt(b² + 4Te²)) / 2     основное изображение, снаружи кольца
T- = (b - sqrt(b² + 4Te²)) / 2     вторичное, зеркальное внутри кольца
усиление = |1 / (1 - (Te/T)⁴)|
```

Это один корень на звезду, и оно даёт настоящие эффекты: звёзды обтекают тень,
двоятся, и вспыхивает кольцо Эйнштейна, когда звезда проходит за дырой.

Аккреционный диск — наклонённое кольцо, затенённое value-noise турбулентностью,
с релятивистским бимингом (сторона, летящая на зрителя, ярче). Плюс почти
круглое вторичное кольцо — это свет с дальней стороны диска, загнутый над тенью.

**Падающая материя.** Отдельный набор звёзд по спирали затягивается внутрь.
Это не интегрирование орбит (либо мелкий шаг, либо накопление ошибки), а прямая
запись того, как ведёт себя распадающаяся орбита: угловая скорость растёт как
`1/r^1.5` (Кеплер), радиальный снос разгоняется как `1/r²`. Получается широкая
медленная дуга, которая на последних радиусах срывается в тугую спираль — глаз
читает это как «затягивает». По дороге орбита выпрямляется в плоскость диска
(так и ведёт себя реальная аккреция), звезда растягивается приливными силами в
штрих, краснеет от гравитационного красного смещения, вспыхивает и пропадает на
границе тени. Половины делятся относительно тени, поэтому звезда, проходящая за
дырой, действительно перекрывается ей.

Цвета диска берутся из `theme.accent` / `theme.accentAlt`, так что дыра
подстраивается под палитру сборки.

## Звук и интро

`assets/uky/sounds.json` регистрирует:
- `uky:intro_impact` (`low.ogg`) — удар в интро
- `uky:menu_music` (`music.ogg`) — зацикленная музыка меню
- `uky:button` (`button_sound.ogg`) — клик по кнопке
- `uky:delete_hold` / `uky:delete_break` — держание кнопки удаления мира
- `uky:heartbeat` / `uky:breathing` — под сценой смерти, `DeathLoop.java`
  подкручивает громкость и питч по ходу сцены (замедляющееся сердце, нарастающее
  дыхание), а не просто проигрывает файл целиком

Интро играет один раз за запуск игры при первом открытии главного меню:
темнота → удар со звуком, вспышка и ударная волна → дыра раскручивается →
проявляется меню. Пропускается любым кликом или клавишей.

Загрузочный экран звук не играет: он работает до инициализации звуковой
системы Minecraft.

## Компоновка главного меню

`mainmenu.layout`:
- `left` (по умолчанию) — леттеринг сверху по центру, меню текстовой колонкой
  слева, чёрная дыра занимает правые две трети. Кнопки без панелей, цвет из
  `theme.accent`, «Выйти» — из `theme.danger`.
- `center` — всё стопкой по центру, кнопки с панелями.

`mainmenu.links` — ряд ссылок под меню, по одной записи в строке:
```
Подпись|https://example.com
Подпись|https://example.com|иконка
```
Третье поле необязательное. Без него иконка подбирается по адресу (YouTube,
Discord, Telegram, Boosty, Twitch, Patreon распознаются отдельно, остальное —
по грубым категориям: видео / чат / донат / репозиторий / прочее). Иконки —
стилизованные марки, нарисованные кодом (`Icons.java`, `LinkIcons.java`), либо
свой PNG из `config/uky/icons/` (имя файла третьим полем). Длинный список сам
переносится на вторую строку. Клик открывает ванильное окно подтверждения
перехода, затем системный браузер. Подробности и полный список ключевых слов
иконок — в [CONFIG.md](CONFIG.md).

## Экран смерти

`GuiDeathScreen` подменяет `GuiGameOver`. Без кнопок: картинка гаснет, идёт
VHS-повреждённая сцена (сканлайны, рвущаяся полоса, дропауты, зерно, распадающийся
на мусорные символы заголовок), под ней сердцебиение и дыхание. Дальше — либо
любая клавиша/клик, либо авто-возврат по таймеру. Выход не мгновенный: плёнку
рвёт сильнее, заголовок разваливается, картинка схлопывается в яркую полоску и
гаснет — и только тогда уходит пакет респавна.

Причина смерти угадывается на клиенте (`DeathTracker`) по последнему известному
состоянию игрока — сервер её не присылает. От неё зависят палитра сцены
(`DeathTheme`), баланс звуков и фраза из `assets/uky/lang/*.lang`
(`uky.death.<причина>.<номер>`). Состояние одной смерти (`DeathScene`) переживает
пересоздание экрана, которое ваниль делает, пока респавн-пакет летит на сервер.

Настройки — категория `death` в конфиге, подробно в [CONFIG.md](CONFIG.md).

## FML-диалоги посреди загрузки мира

Экран вроде «в сейве отсутствуют блоки — продолжить?» рисуется не игровым циклом:
пока стартует мир, клиентский поток стоит в ожидании сервера, и единственное, что
его отрисовывает и читает ввод — `FMLClientHandler.handleLoadingScreen`, вызванный
из `LoadingScreenRenderer.setLoadingProgress`. `UkyLoadingScreen` перехватывает
именно этот путь, поэтому такой вопрос дополнительно прокручивается на 60 fps в
`UkyLoadingScreen.pumpStartupQuery`, пока не получит ответ — иначе он рисовался бы
на паре кадров в секунду и не видел бы кликов. `GuiStartupQueryScreen` — тот же
экран в нашем стиле: заголовок отдельно от списка, список скроллится, длинные
строки переносятся, Escape отвечает «нет», а не вешает загрузку.

## Ассеты
- Мод не поставляет ни фон, ни логотип — только шрифт и звуки.
- `assets/uky/textures/gui/logo.png` — **опционально**. Если файла нет, и в меню,
  и на загрузочном экране рисуется текстовый леттеринг из `mainmenu.title`.
- `assets/uky/textures/gui/background.png` — нужен только при
  `effects.background=image`. Если файла нет, режим тихо откатывается на `solid`.
- Загрузочный экран смотрит в `config/uky-splash/background.png` и
  `config/uky-splash/logo.png`. По умолчанию там ничего нет и экран чисто чёрный —
  это и есть задуманный вид; картинка появится только если её туда положить.
- `config/uky/icons/` — картинки для ссылок главного меню (см. ниже и
  [CONFIG.md](CONFIG.md)). Создаётся сама при первом запуске.

## Конфиг
`config/uky/uky.cfg` (у себя же, рядом с `config/uky/icons/`), категории:
- `screens` — какие ванильные экраны подменять, включая экран смерти
- `death` — длительность сцены, авто-возврат, сила VHS-эффектов, звук
- `effects` — `background` (`blackhole` / `image` / `solid`), частицы, виньетка,
  зерно, scanlines, дрейф фона, звуки кнопок
- `mainmenu` — какие пункты показывать, леттеринг, подпись, футер (левый и
  правый), `intro` (интро с ударом), `music`, `musicVolume`, ссылки и папка
  их иконок
- `splash` — включён ли свой загрузочный экран, показывать ли подсказки, сами
  подсказки (ship'ится пять примеров, не пустой список)
- `theme` — 7 базовых цветов `0xRRGGBB`, из них выводится вся остальная палитра

Все значения по умолчанию объявлены **только** в полях `UiConfig` — не
дублируются при чтении, чтобы правка дефолта не расходилась с тем, что реально
пишется в файл. Файл переписывается при каждом запуске: Forge считает конфиг
изменившимся только когда поменялось значение, а не комментарий, поэтому иначе
перевод/переформулировка комментария не долетала бы до уже существующих
установок. Значения при этом не трогаются, обновляется только текст.

Старый `config/uky.cfg` (до переноса в подпапку) переносится в новый путь
автоматически при первом запуске, значения сохраняются.

Загрузочный экран читает конфиг сам (до pre-init), поэтому файл лежит по
фиксированному пути.

Если загрузочный экран глючит на какой-то видеокарте — `splash.customSplash=false`,
игра вернётся к форджевому. Любая ошибка внутри нашего сплэша тоже приводит к
откату на форджевый, а не к падению игры.

Полное описание всех ключей, с примерами — [CONFIG.md](CONFIG.md).
